# 1.2 自動影片分析增量規格

## 操作與輸出

匯入並選學員 → 自動啟動本機模型 → 抽樣影格進度 → 報告自動儲存 → 時間連結及骨架核對 → 建議練習 → 加入計劃／記錄改善。既有影片可重新分析。持拍手取自學員記錄，使用者可改左右手／鏡像後重新分析。

報告區分：數字量度（2D 角度、像素相對位移）、規則觀察（需教練核對）、無法判斷項目。沒有百分制技術分數。可用影格比例只反映偵測輸出符合可見度門檻，不是模型準確率。

## 原生處理

`PoseEngine.kt` 使用 `com.google.mlkit:pose-detection:18.0.0-beta5`，bundled base model、CPU、STREAM_MODE。背景單一 worker；每 125ms 選一個影格，可靠時間軸時以實際索引解碼及去重，否則標示近似時間。影格長邊最多 960，只保留單個解碼 bitmap；不保存臉部關鍵點，只保存 11–32 身體／手腳點及畫面座標、inFrameLikelihood。該值不是關節位置正確機率。

MethodChannel 的 analyze / cancel 與 progress 有 job ID，防止舊工作回覆覆蓋新報告。輸入只能是 App 私有、存在的影片，最多 180 秒、16MP；每次只執行一項分析。取消、離開 App、Activity 結束均停止後續影格；當前單次模型處理有 45 秒上限。bitmap、retriever、detector 用 finally 釋放。

## 規則版本 clear-observations-1

- 點必須在畫面內且 inFrameLikelihood ≥0.70；分析須最少 12 個可用全身影格、全片可用比例 ≥60%。解碼圖寬高至少 360px、肩髖中點距至少 45px。這些是工程品質閘，並非運動員標準。
- 手腕相對肩膊高度，以當格肩髖長度正規化。找連續抬高手腕群組（高於肩膊 0.45 軀幹長度），取最大高度作定位；群組至少兩格，不能持續超過 2.5 秒。
- 須在峰值前 0.25–1.5 秒及後 0.25–1.75 秒看見手腕高度降低至少 0.35 軀幹長度，才列為疑似完整頭頂揮拍；不能確認接觸羽毛球、出球類型，也可能把非羽毛球動作列為疑似。
- 影格缺口 >375ms、軀幹尺寸比跳變超過約 1.67 倍、相鄰髖中點移動 >0.8 軀幹長度，整個動作窗口棄用。
- 準備手肘提示：峰值前一秒內至少三個影格且 ≥60%，持拍肘比肩低超過 0.2 軀幹長度。
- 非持拍手提示：準備窗口至少三個可信手腕影格且覆蓋 ≥75%，全部低於同側肩膊。
- 揮拍後傾斜提示：至少三格且 ≥40%，肩髖中線偏離畫面垂直線 >25°。鏡頭傾斜、正常移動也會觸發，所以不直接宣稱失平衡。
- 舉手峰值肘角、揮拍後最大傾角及雙腳中點淨位移只描述鏡頭平面，先以真實像素長寬計算，不能當 3D 角度、力學重心、補步次數或回位分數。

門檻是保守的可重現工程啟發式，未用兒童資料校準。教學建議沿用低強度教練練習庫，最多三項；不自動訓斥學員、不診斷傷患、不判定握拍／轉身／剪刀步錯誤。

## 儲存與擴展

DB version 2 以 onUpgrade 新增 pose_reports(id, video_id, result JSON, plan_id?, created) 及索引。原有表與資料不重建。每影片最多三份報告；影片／學員刪除則骨架與報告級聯清除。從報告加入計劃使用同一交易並具冪等性，不覆蓋教練人工評估。規則版本、模型版本、左右手、鏡像、原生時間及品質狀態均記錄。

沒有 GPT、雲端備份或上傳端點。release 網絡權限透過 manifest merger 移除且實際 APK 檢查；SDK 的模型在 APK 內。ML Kit 為專有 SDK，並不宣稱全開源。

## 驗證與尚未覆蓋範圍

新增單元回歸、SQLite 遷移與刪除、Android 真實模型離線 smoke test、取消與骨架／報告 UI 整合。模型 smoke test 使用 Google MediaPipe 公開測試圖轉為短片，只證明推理運作且靜態姿勢不應虛構羽毛球揮拍。

尚未取得具適當同意、人工標註的兒童羽毛球影片；不聲稱已驗證球技準確率。後續驗收須涵蓋左右手、前／側／背面、直／橫／旋轉影片、多人、遮擋、移動鏡頭、不同體型及手機，與人工標註比較時間及角度誤差。背面／側面遮擋可能不能分析，普通人體模型不能分清所有技術。
